# CLI distribution verification requirements

These requirements track the live implementation of the
[CLI distribution verification specification](index.md).

| ID | Requirement | Implementation | Verification | Documentation | Evidence |
|---|---|---|---|---|---|
| CLIDIST-001 | The shipped bundled-Python runtime and config-specific optimized PyInstaller bundle remain distinct distributions with separate plugin policies and test suites. | Implemented | Automated | Documented | Runtime-layout and frozen dynamic-install tests; [current implementation](../../cli-distribution.md) |
| CLIDIST-010 | The source-installation smoke boots the default config from a fresh lean Core/application venv and clean files, dynamically installing default `path:` plugins into the clean config-owned cache. | Implemented | Automated | Documented | `test_cli_distribution_levels.py::test_level_1_clean_python_environment_boots_default_config`; `npm run test:cli:clean-env` passed on macOS ARM64 |
| CLIDIST-020 | The extracted-archive smoke independently unpacks a current-platform shipped archive, executes its launcher directly, boots a default-derived config, and dynamically installs a designated packaged plugin that is absent from the preinstalled manifest into a fresh user cache. | In progress | Unverified | Pending | Direct archive boot and structural checks exist; dynamic non-preinstalled plugin installation and descriptive naming are tracked in `tasks/20260908-cli-distribution-test-levels.md` |
| CLIDIST-030 | The default-installer smoke independently runs the public download installer with its default install root, command name, and automatic PATH-directory selection; it invokes `crystal-lattice` by name, boots a default-derived config, and dynamically installs the designated non-preinstalled packaged plugin into its own fresh cache. | In progress | Unverified | Pending | Temporary-path Python-installer coverage exists; public default-installer, PATH discovery, and dynamic plugin installation are tracked in `tasks/20260908-cli-distribution-test-levels.md` |
| CLIDIST-040 | Root npm commands independently run the source-installation, extracted-archive, and default-installer acceptance scenarios through the same direct scenario entry points used by CI. | In progress | Unverified | Pending | Existing root commands invoke pytest-backed scenarios; direct shared npm/CI entry points are tracked in `tasks/20260908-cli-distribution-test-levels.md` |
| CLIDIST-050 | Every native release-matrix target runs both the extracted-archive and default-installer root npm commands against the one archive built by that target. | In progress | Unverified | Pending | Native archive smoke passed in [run 34328869249](https://github.com/dynamicprogrammingsolutions/crystal-lattice/actions/runs/34328869249); installed-command matrix coverage and npm invocation remain |
| CLIDIST-051 | The extracted-archive and default-installer smokes share no mutable home, workspace, config directory, plugin cache, pip cache, installation directory, or command directory; neither smoke invokes or depends on the other, and each can produce its own result after archive construction succeeds. | Not started | Unverified | Pending | Post-completion follow-up in `tasks/20260908-cli-distribution-test-levels.md` |
| CLIDIST-052 | Each archive-based smoke begins with no plugin-installation state, verifies that its designated probe plugin is not listed as preinstalled, triggers a real installation through the packaged runtime, and asserts plugin-specific installation metadata in that smoke's cache. | In progress | Unverified | Pending | Fresh empty caches exist, but archive-based smokes currently require the cache to remain empty |
| CLIDIST-060 | A new default config starts and exposes all configured agents when its external `${env:...}` values are absent from the process and discovered `.env` files. | Implemented | Automated | Documented | Shared boot helper plus source-installation, extracted-archive, and installed-command smokes passed; [configuration guide](../../../configuration.md) |
| CLIDIST-061 | Normal CLI use does not require shell exports: the CLI loads credentials from documented config, project, user, and discovered `.env` files without mutating the process environment. | Implemented | Automated | Documented | `test_cli_environment_isolation.py`; `test_application_layer_config.py`; [placeholder guide](../../../configuration-placeholders.md) |
| CLIDIST-062 | Distribution startup performs no provider/tool API request, synthesizes no credential, and leaves request authentication to the selected provider or tool contract. | Implemented | Automated | Documented | Shared boot helper calls only local readiness and agent-list endpoints; all three delivered smoke paths passed without dummy values |
| CLIDIST-063 | The config loader classifies each unresolved `${env:...}` reference as a nonfatal `env_missing` warning with its variable and config path; independently invalid resolved structures retain their normal fatal validation. | Implemented | Automated | Documented | `agent_app.config.resolve_placeholders`; `test_config_env_substitution.py`; `test_application_config_errors.py`; [placeholder guide](../../../configuration-placeholders.md) |
| CLIDIST-070 | Archive construction completes in an isolated build environment before archive-consuming tests start and cannot install or upgrade packages in the repository test environment. | Implemented | Automated | Documented | Root runner waits for isolated Nox build; two archive builds passed and repository `pip freeze` hash remained unchanged |
| CLIDIST-071 | The default local archive build provisions an `uv`-managed Python 3.11 runtime equivalent to the release runtime family; explicit runtime and prebuilt-archive overrides remain optional. | Implemented | Automated | Documented | Nox provisioned managed CPython 3.11.16; archive portability and boot smoke passed |
| CLIDIST-072 | Boot-probe cleanup owns the full process tree on POSIX and Windows, applies bounded graceful and forced termination, and verifies that the server port closes. | Implemented | Automated | Documented | POSIX helper/integration tests; native Windows `.cmd` archive boot and cleanup passed in [run 34328869249](https://github.com/dynamicprogrammingsolutions/crystal-lattice/actions/runs/34328869249) |
| CLIDIST-080 | Without an explicit bin-directory override, the public installer selects an existing suitable writable directory already present on PATH and installs the `crystal-lattice` command there, making it resolvable by name immediately in the supported terminal environment. | Not started | Unverified | Pending | Post-completion follow-up in `tasks/20260908-cli-distribution-test-levels.md` |
| CLIDIST-081 | Default bin-directory selection is deterministic, prefers an existing installation and conventional user command directories, rejects unsafe or unusable PATH entries, and fails before installation with an actionable message when no suitable PATH directory exists; an explicit override remains supported. | Not started | Unverified | Pending | Post-completion follow-up in `tasks/20260908-cli-distribution-test-levels.md` |
| CLIDIST-090 | Specifications, current documentation, commands, tests, and diagnostics use descriptive scenario and component names; any retained historical “level” terminology is introduced with its meaning rather than assumed. | In progress | Unverified | Pending | Specification index defines the names; current docs and code identifiers still use level terminology |
| CLIDIST-091 | Distribution acceptance orchestration has one direct implementation per scenario; local npm commands and GitHub Actions call those same entry points, while shared code is limited to lower-level build, extraction, configuration, boot, and process-cleanup helpers that cannot substitute one scenario for another. | Not started | Unverified | Pending | Post-completion follow-up in `tasks/20260908-cli-distribution-test-levels.md` |

## Current-state note

The original source, archive, and temporary Python-installer checks have
automated evidence, including native archive execution on every release
target. The strengthened direct archive, public default-installer,
dynamic-plugin-installation, PATH-discovery, shared npm/CI entry-point,
terminology, and simplification requirements are not yet implemented or
verified.
