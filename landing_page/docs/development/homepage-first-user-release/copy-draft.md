feel broad until the full product image appears.

## Shared product overview copy

The following copy can follow any selected opening direction, with minor
reconciliation to avoid repetition.

### Section: Product at a glance

Eyebrow:

> Product overview

Heading:

> Sessions, setup, and current work stay in one workspace.

Body:

> Sessions are more than a scrolling transcript. The session list, selected
> conversation, composer, profile, tools, and current work remain available
> from the same application.

Figure title:

> Desktop workspace

Caption:

> The session list and selected conversation stay visible together, so you can
> recognize work, return to it, and continue from the composer.

Supporting labels:

- Persistent sessions
- Reusable profiles
- Provider and feature controls
- Desktop and mobile clients

### Section: Visible, configurable, and extensible

Eyebrow:

> Change what matters

Heading:

> Keep the useful defaults without hiding the parts that affect the work.

Introduction:

> Crystal Lattice separates three related ideas: seeing the active behavior,
> configuring a session's setup, and extending or replacing product behavior.

#### Proof 1

Title:

> Response details stay with the work.

Body:

> Provider-supported usage, token, cache, duration, reasoning, and cost
> information can remain attached to the work instead of disappearing behind
> a generic chat result.

Figure title:

> Response usage and cost

Caption:

> The completed response keeps its available usage, cache, duration, and
> estimated-cost information close to the conversation.

#### Proof 2

Title:

> A profile changes the setup—not only the model.

Body:

> The Agent picker selects a reusable profile with instructions, tools, model
> and provider defaults, and other behavior used by the session.

Figure title:

> Profile and included tools

Caption:

> The selected profile explains its purpose and shows the tools it contributes
> before you use it in a session.

#### Proof 3

Title:

> Provider-specific behavior can become real UI.

Body:

> A provider or feature plugin can contribute controls or reporting where they
> are useful. A setting such as reasoning effort does not need to be hidden in
> a separate configuration file or hardcoded into every client.

Figure title:

> Provider controls

Caption:

> Reasoning effort and verbosity appear as session controls when the active
> provider path supports them.

### Section: Desktop and mobile

Eyebrow:

> Continue from another screen

Heading:

> Desktop and mobile open the same Crystal Lattice sessions.

Body:

> Crystal Lattice runs on your computer. Desktop and mobile are clients for
> the sessions there, so another screen does not create a separate copy of the
> conversation.

Figure title:

> One session, two clients

Caption:

> Matching session identity and conversation content show the same work open
> in Desktop and mobile.

Supporting sentence:

> Connect directly on the same local network, or use a Crystal Lattice bridge
> when the phone is away from that network.
