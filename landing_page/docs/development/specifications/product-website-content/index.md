# Product Website Content Specification

This package-owned specification defines what the Crystal Lattice product
website must communicate and what visitors must be able to understand and do.

It is intentionally separate from the
[website content system](../../content-system.md), which documents how YAML,
Markdown, Astro components, and public files produce HTML.

## Scope

The specification owns:

- visitor understanding of the product;
- audience and action-path priorities;
- coding-agent and broader-agent positioning boundaries;
- compatibility-profile and official-product distinctions;
- current, optional, partial, experimental, planned, unsupported, and
  not-applicable communication;
- transparency and open-source communication;
- mobile, desktop, local-network, and bridge explanation;
- proof expectations;
- progressive evidence-informed revision;
- contributor-facing content outcomes.

It does not define:

- YAML or Markdown schemas;
- Astro rendering;
- component behavior;
- screenshot-generation implementation;
- provider, plugin, configured-agent, bridge, mobile, desktop, or CLI
  behavior;
- release metadata contracts owned by release packages.

## Specification Documents

- [Content specification](content-spec.md): target visitor understanding,
  content principles, audience paths, claim boundaries, proof, and progressive
  revision.
- [Requirements](requirements.md): stable target outcomes with implementation,
  verification, documentation, and evidence state.

Additional specification pages or decision records are added only when a
substantial content-domain concern cannot be explained clearly in the current
documents.
