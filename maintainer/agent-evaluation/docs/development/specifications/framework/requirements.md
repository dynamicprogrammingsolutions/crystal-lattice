# Agent evaluation framework requirements

These requirements define the reusable `agent_eval` kernel. The Crystal
Lattice environment and documentation-guidance suite have separate
requirements.

| ID | Requirement | Implementation | Verification | Documentation | Evidence |
|---|---|---|---|---|---|
| AEVAL-001 | A maintainer-owned Python package exposes a generic evaluation kernel under the `agent_eval` import without making it public product documentation. | Implemented | Automated | Documented | `maintainer/agent-evaluation/`; package import tests; Checkpoint 1 |
| AEVAL-002 | `AgentEval.run(name, program, *, environment=None, continue_from=None, workspace=None, cache_key=None)` is the minimal stable kernel execution contract. | Implemented | Automated | Documented | `src/agent_eval/eval.py`; exact-signature test; README |
| AEVAL-003 | The generic kernel owns run identity, workspace, cache, parent linkage, artifacts, and error preservation without hardcoding agent prompts, messages, tool loops, snapshots, assertions, scoring, or presentation. | Implemented | Automated | Documented | Generic kernel tests; no Core/Application imports; README |
| AEVAL-004 | A single `RunEnvironment` contract provides the broad replacement seam for context creation, compatibility fingerprinting, state restoration/snapshotting, and environment-specific final observations. | Implemented | Automated | Documented | `src/agent_eval/environment.py`; replay-environment substitution and continuation tests |
| AEVAL-007 | A program may perform arbitrary Python and multiple environment operations and may return any Python value through `Run.value`. | Implemented | Automated | Documented | Arbitrary-value and multi-operation tests; README |
| AEVAL-008 | `Run` exposes the program value, reusable environment snapshot, finalized environment observation, workspace, changed paths, artifact location, error, and concise helpers without assigning a framework-owned verdict. | Implemented | Automated | Documented | `src/agent_eval/result.py`; success/failure/cache tests; README |
| AEVAL-009 | A run can continue from an immutable hash-verified parent snapshot in a compatible environment and clean workspace while preserving parent and restore/rebase provenance. | Implemented | Automated | Documented | Continuation, incompatibility, no-snapshot, custom-codec, and Git-workspace tests |
| AEVAL-010 | Explicit cache keys reuse compatible expensive runs using environment, workspace, parent, and schema fingerprints and reject incompatible or partial cache entries. | Implemented | Automated | Documented | Cache hit/corruption/incomplete/concurrency tests; README |
| AEVAL-011 | Existing paths and arbitrary workspace factories are supported, and an optional Git helper provides pinned revisions, clean workspaces, status, changed paths, and diffs. | Implemented | Automated | Documented | Git workspace, cleanup, cached tracked/untracked restoration, and existing-path tests |
| AEVAL-012 | Every run writes compact deterministic canonical artifacts and separately retained raw environment/workspace/failure evidence, including useful error-phase information. | Implemented | Automated | Documented | Artifact/failure/cache-evidence tests; Checkpoint 1 and 2 samples under `tmp/agent-evaluation-checkpoint*/`; package docs |
| AEVAL-013 | Artifact handling excludes credentials/authentication state, uses ignored local output by default, and permits environment-owned redaction, projection, and retention behavior. | Implemented | Automated | Documented | Generic redaction/path safety, hashed Crystal Lattice environment values, explicit projections/presentations, canonical/raw/internal visibility regression coverage, and ignored local output verified |
| AEVAL-014 | Deterministic tests cover arbitrary program values, environment substitution, continuation, cache validation, workspace handling, result files, and failure preservation without depending on one environment implementation. | Implemented | Automated | Documented | Generic kernel and alternate-environment tests; package test suite |
| AEVAL-015 | Pytest is the initial suite runner; real-model tests are explicitly marked and excluded from normal default tests, hosted execution is gated, and skipped gated tests are not counted as verification. | Implemented | Automated | Documented | Package pytest configuration registers/excludes `agent_eval`; GLM/GPT profiles and explicit real/hosted gates exercised |
| AEVAL-017 | The former combined real-model provenance requirement is removed from the generic kernel contract. Kernel persistence remains covered by `AEVAL-012`; Crystal Lattice review provenance and suite-specific inputs, outputs, assessments, and presentations are owned by their respective specifications. | Removed | Not applicable | Documented | Ownership correction in task 095; `CLEVAL-001`–`CLEVAL-004`; `TGEVAL-012`–`TGEVAL-017`; result-package specification |
| AEVAL-018 | Maintainer documentation explains the generic kernel, environment contract, cache, continuation, evidence and result storage, pytest workflow, and environment substitution without making one bundled environment part of the kernel contract. | Implemented | Automated | Documented | Concise README, conceptual docs home, core concepts and data flow, package AGENTS guidance, parsed Python examples, and valid relative links |
| AEVAL-019 | After implementation and representative real-model runs, a dedicated calibration review evaluates seed/test cost, redundancy, diagnostic value, and missing clarity signals; proposed removals, replacements, or additions are presented with evidence and require user approval before the specification or suite changes. | Implemented | Human verified | Documented | August 10 post-implementation keep/replace/sentinel proposal in subtask 015; user approval on August 11, 2026; approved Test 16 replacement and sentinel policy applied |

`AEVAL-017` previously combined three owners: generic run persistence,
Crystal Lattice instruction/session/request provenance, and consumer-suite
assessment/presentation provenance. It is retained as a removed requirement so
historical task references remain interpretable. No replacement generic kernel
requirement is needed.
