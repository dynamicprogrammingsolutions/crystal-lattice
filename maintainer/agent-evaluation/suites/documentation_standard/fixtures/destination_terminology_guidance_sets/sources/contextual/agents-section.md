Context means where wording comes from, where it is used, and its audience.
Requests, tasks, specifications, files, and review comments provide source
context; each file or record has its own context. Use source context to
understand behavior; choose terms and organization for that context. Replace
inherited planning or tracking terms unless required or established by the
product, public interface, or domain.

Examples: a task heading named “Deployment workstream” does not become a
specification heading; an inherited “Implementation checkpoint” heading in
user documentation is replaced with the supported capability; an established
public `retry_after` field remains exact.
