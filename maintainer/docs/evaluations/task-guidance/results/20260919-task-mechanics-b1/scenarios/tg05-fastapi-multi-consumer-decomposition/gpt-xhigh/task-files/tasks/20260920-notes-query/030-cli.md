# Expose notes queries through the CLI

Own the public `notes list` command's query options and output, and provide
the decisive proof that the CLI uses the production reusable client against
the FastAPI service.

Parent Task: tasks/20260920-notes-query/000-main.md

Depends On: tasks/20260920-notes-query/010-api-contract.md,
tasks/20260920-notes-query/020-reusable-client.md

## Requirements checklist

- [ ] `notes list` exposes the approved pagination, stable-sorting, and
  optional text-filtering options using documented CLI names and types.
- [ ] The CLI forwards those options through the production
  `NotesClient` surface and renders the approved result shape.
- [ ] An unparameterized `notes list` retains its current listing behavior.
- [ ] CLI integration evidence crosses the real CLI entry point, reusable
  client, and FastAPI service path.

## Scope and boundary

This subtask owns `apps/notes_cli/cli.py`, the CLI README, CLI argument/output
tests, and the production-path integration test. It does not change the API
contract or duplicate client request construction.

## Research and supporting facts

- `apps/notes_cli/cli.py` currently registers only a `list` subcommand with no
  arguments.
- `list_command(client)` calls `client.list_notes()` and prints each note as
  `<id>: <title>`.
- Existing CLI tests inject a local `Client` fake, so they do not prove the
  production client-to-service path requested by this task.
- `apps/notes_cli/README.md` currently documents only `notes list`.

## Execution plan

Status: Draft

1. Read the settled API and Python client contracts and choose CLI option
   names/types that are an explicit documented mapping, resolving any
   presentation questions before implementation.
2. Extend the `list` parser and command flow to pass only supported options to
   `NotesClient.list_notes(...)`; preserve the current no-argument output.
3. Add focused parser/output tests for the CLI surface and invalid argument
   handling.
4. Add the decisive integration test by invoking the public CLI entry point
   with a real `NotesClient` connected to the FastAPI app (for example,
   using the existing `TestClient` as the transport), then assert output
   reflects service-side filtering, pagination, and ordering.
5. Update `apps/notes_cli/README.md` with exact options, examples, and the
   preserved unparameterized command.

### Implementation decisions and open questions

- Decision: the decisive CLI test must instantiate the production
  `NotesClient`; the existing fake-client test remains useful only for local
  rendering behavior.
- Decision: CLI flags map to the reusable client's approved keyword surface
  rather than constructing HTTP query parameters in the CLI.
- Open: exact flag names, whether sort direction is exposed, and whether any
  response metadata needs CLI rendering depend on the API/client contract.
