# Expose notes-query through the CLI and prove the live consumer path

Add user-facing query controls to `notes list`, preserve default output, and
own the end-to-end check that exercises the production CLI, Python client, and
FastAPI service together.

## Requirements checklist

- [ ] Add CLI options for the approved pagination, sorting, and filtering
      controls.

      unparameterized request.
- [ ] Render parameterized results according to the approved client/API

## Supporting facts

The CLI parser currently has only a required `list` subcommand. `main()`
selects an injected client when supplied, otherwise it calls
`NotesClient.from_environment()`. The current `list_command()` prints each
note as `<id>: <title>`, and its only test supplies a fake client. The
decisive new check must omit that injection and set `NOTES_API_URL` to the
live service.

## Execution plan

Status: Draft

Add parser options only after the API and client vocabulary is frozen. Pass
parsed values to the client using the approved omission/default rules, while
keeping the no-option path equivalent to the current `list_command()` call.
If the API returns an envelope, render its item collection according to the
approved contract; if it remains an array, preserve the current iteration
model. Keep presentation concerns in the CLI rather than changing client
data semantics.

Retain focused parser/output tests with a fake client for local CLI behavior,
but make the decisive acceptance test start a real service process on an
ephemeral localhost port, seed or create notes, set `NOTES_API_URL`, and
invoke the CLI entry path with no injected client. Exercise at least one
filtered, bounded, sorted request and assert the printed result and absence
of excluded notes. Identify the supported ASGI server and any narrowly
scoped test dependency needed to make this process boundary reproducible.

### Implementation decisions and open questions

  user-facing behavior.
- The live-path harness must use a real HTTP process and the normal
  environment-based client construction; test doubles remain supplementary.

### Documentation
