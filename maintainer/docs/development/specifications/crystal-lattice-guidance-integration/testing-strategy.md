# Crystal Lattice guidance integration testing strategy

Verification includes:

- root and package link and routing checks;
- documentation-site registry, assembly, navigation, and build tests;
- exact root-guidance compilation and task-guidance synchronization;
- package-specific migration checks;
- documentation-guidance behavioral scenarios using explicit instruction
  delivery provenance;
- destination-terminology scenarios that keep new-label prevention separate
  from confirmation before existing-wording cleanup;
- frozen producer, semantic, and pairwise records where valid;
- human review for clarity and acceptance.

A run is incomplete when a required producer output, semantic record, or
pairwise record is missing. Direct injection is not reported as discovery, and
task-mode integration is not accepted until a real task file is produced and
assessed.

Destination-terminology candidate acceptance uses compiled workspace
`AGENTS.md`, the normal Crystal Lattice system-message feature, matching
model-family tools, and exact source/output/delivery provenance. A separate
structured judge may assess confirmation quality only after deterministic
producer findings pass; its result remains supporting evidence.

Task-guidance verification additionally uses:

- three bounded task-handoff contracts and three substantial decomposition
  contracts;
- independent task-creation and plan-preparation stage matrices;
- fresh-agent and same-agent continuity chains;
- retain-plan and omit-plan variants;
- semantic task topology, requirement, decision, dependency, and crossing
  assessment;
- quality-gated investigation-efficiency evidence;
- B0 and B1 baseline reports before guidance-placement candidates;
- focused v3/v4/v5 comparison before a full confirmation matrix.

The task-guidance suite specification and strategy live under
`maintainer/agent-evaluation/suites/task_guidance/docs/development/`.
