# Provider-Native Settings UI

Make provider-native capabilities more visible and easier to demonstrate in the
UI, especially for the model-native harness positioning.

## Requirements checklist

- [ ] Audit which provider-native settings are already exposed by built-in plugins.
- [ ] Prioritize visible controls such as reasoning effort, verbosity, web search, prompt caching, native compaction, attachment modes, usage, and cost metadata.
- [ ] Add or simplify UI controls where the current flow is too hard to demonstrate.
- [ ] Prepare reliable screenshot/demo states for the landing page.
- [ ] Add tests for UI schema exposure where new controls are added.

Parent Task: `tasks/20260611-landing-page-positioning-update/000-main.md`

## Context

The model-native claim is stronger when users can see native behavior in the UI.
Examples include reasoning effort, verbosity, web search and citations, native
compaction, prompt caching, image/PDF attachment handling, and usage/cost
metadata.
