## Background

The current binary bundle copies plugin source trees into
`_internal/bundled_plugins` and sets `BUILTIN_PLUGINS` to that directory. At
runtime, the plugin installer special-cases paths under a directory named
`bundled_plugins`: it activates plugin source directories directly and skips
`pip install --target`.

That means plugin source code is present, but dependencies declared in the
plugin project's own `pyproject.toml` are not installed unless they also happen
to be dependencies of `crystal-lattice-cli` or `agent-core`.

During `0121.5` installed-bundle validation, this surfaced as
`openai_responses` failing to import `openai`. Adding `openai` to the CLI
package would hide that single symptom while leaving the generic bundled plugin
dependency problem intact. This task should fix the boundary correctly.

The desired production behavior is selected preinstall: default/release plugins
are installed with their dependencies during bundle build, while optional plugin
modes can be handled later.
