# Cloud Profile Schema And Script Conventions
Refine the cloud profile schema and bundled script layout so profile script locations are derivable by convention, repo-local stage/install hooks are optional, and every bundled script is self-documented.

## Requirements checklist

- [ ] Remove redundant `cloud_setup_profile` and `install_profile` references from `transfer_up_profiles`, replacing them with direct `cloud_setup_script` and `install_script` fields.
- [ ] Make `local_stage_script` and `install_script` repo-local optional hooks under the current working directory, and skip them cleanly when the file does not exist.
- [ ] Reorganize bundled scripts under `application/python/agent_terminal_app/default_config/cloud-agent/profiles/` so their paths are derivable directly from config keys and profile ids.
- [ ] Define and apply one stable naming convention for bundled transfer-up and sync-down script paths.
- [ ] Add clear header comments to every bundled script covering purpose, required env vars, expected inputs/outputs, and customization guidance.
- [ ] Update resolver, plugin, runtime, docs, and tests to match the simplified schema and optional-hook behavior.
- [ ] Preserve the current shipped profile behaviors and the local-Docker orchestrator profile e2e coverage while making these structural changes.

## Background

Task `0121` introduced:

- bundled default cloud profile families
- a separate `cloud_setup_profiles` section
- optional `local_stage_script` support
- local-Docker orchestrator e2e coverage for the shipped standard profile families

After review, the next refinement should simplify the configuration and make the shipped script layout easier for users to navigate and customize without consulting the code or config implementation details.

The requested adjustments are:

- flatten `transfer_up_profiles` so each entry directly names its `cloud_setup_script` and `install_script`
- make `local_stage_script` and `install_script` point into `${env:WORKING_DIR}` and no-op when absent
- make bundled script locations follow a stable convention that matches the config structure
- document every bundled script in-place

## Proposed Direction

The follow-up should simplify the shape of `transfer_up_profiles` to something conceptually like:

```jsonc
"transfer_up_profiles": {
  "working-tree-current-state": {
    "local_stage_script": "${env:WORKING_DIR}/.cloud-agent/local-stage",
    "local_transfer_script": "${env:CONFIG_DIR}/cloud-agent/profiles/transfer_up/working-tree-current-state/local_transfer_script",
    "cloud_setup_script": "${env:CONFIG_DIR}/cloud-agent/profiles/transfer_up/working-tree-current-state/cloud_setup_script",
    "install_script": "${env:WORKING_DIR}/.cloud-agent/install-cloud",
    "compatible_sync_down_profiles": ["working-tree-patch"]
  }
}
```

And sync-down entries should map directly to predictable bundled paths such as:

```jsonc
"sync_down_profiles": {
  "working-tree-patch": {
    "cloud_export_script": "${env:CONFIG_DIR}/cloud-agent/profiles/sync_down/working-tree-patch/cloud_export_script",
    "cloud_mark_synced_script": "${env:CONFIG_DIR}/cloud-agent/profiles/sync_down/working-tree-patch/cloud_mark_synced_script",
    "local_apply_script": "${env:CONFIG_DIR}/cloud-agent/profiles/sync_down/working-tree-patch/local_apply_script"
  }
}
```

That keeps the config and filesystem structure aligned:

- `transfer_up/<profile-id>/<script-key>`
- `sync_down/<profile-id>/<script-key>`

Repo-local hooks should not need bundled wrapper scripts. The application should check whether the configured path exists before attempting to run or package it.
