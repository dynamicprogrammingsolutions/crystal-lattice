# Cloud Config Assets Include Excluded
Add a generic opt-in mechanism for copying selected config assets that are normally excluded, so secrets such as `.env` files or `auth/chatgpt-auth.json` can be transferred intentionally without copying whole secret directories by default.

## Requirements checklist

- [ ] Add `application.cloud_agent.config_assets.include_excluded` as a generic list of relative paths or glob-style patterns evaluated under `CONFIG_DIR`.
- [ ] Preserve the current default exclusions for `.env`, `.env.*`, `.plugin_cache`, `logs`, `sessions`, `auth`, and `state`.
- [ ] Let an entry in `include_excluded` copy a file or directory even when it matches `config_assets.exclude`.
- [ ] Keep copying safe: reject or skip absolute paths, `..` escapes, symlinks, unreadable entries, and entries over the existing top-level size limit.
- [ ] Preserve relative paths under the cloud config assets directory, e.g. `auth/chatgpt-auth.json` should become `${CONFIG_DIR}/auth/chatgpt-auth.json` inside the cloud runtime.
- [ ] Record manifest metadata that distinguishes normal copied files from files copied because of `include_excluded`, without logging or returning file contents.
- [ ] Add unit tests for default behavior, explicitly included `.env`, explicitly included `auth/chatgpt-auth.json`, and exclusion of non-included files under an excluded directory.
- [ ] Update cloud-agent docs and default-config reference docs with examples for `.env.cloud`, `.env`, and `auth/chatgpt-auth.json`.

## Background

Cloud runtime config transfer already has a generic config/environment transfer layer in:

```text
plugins/cloud-agent-app/src/cloud_agent_app/cloud_agent_transfer.py
```

The relevant functions are:

```python
prepare_cloud_transfer(...)
copy_config_assets(...)
write_runtime_env(...)
```

The default config intentionally excludes broad secret/config state paths:

```json
"config_assets": {
  "include_config_dir": true,
  "exclude": [
    ".env",
    ".env.*",
    ".plugin_cache",
    "logs",
    "sessions",
    "auth",
    "state"
  ],
  "max_top_level_entry_bytes": 104857600
}
```

That means the cloud runtime currently does not receive:

```text
${CONFIG_DIR}/auth/chatgpt-auth.json
```

Both the ChatGPT auth app and OpenAI Responses ChatGPT auth feature default to that generic config-relative path when no explicit credentials path is configured:

```text
auth/chatgpt-auth.json
```

Simply removing `"auth"` from the default exclusion would likely make ChatGPT auth work, but it would copy the entire local `auth` directory. This task should provide a generic narrower mechanism so users can explicitly opt in only the files they intend to transfer.

## Proposed Config Shape

Example for ChatGPT credentials:

```json
{
  "application": {
    "cloud_agent": {
      "config_assets": {
        "include_config_dir": true,
        "exclude": [
          ".env",
          ".env.*",
          ".plugin_cache",
          "logs",
          "sessions",
          "auth",
          "state"
        ],
        "include_excluded": [
          "auth/chatgpt-auth.json",
          "auth/chatgpt-rate-limits.json"
        ],
        "max_top_level_entry_bytes": 104857600
      }
    }
  }
}
```

Example for an intentionally cloud-safe env file:

```json
{
  "application": {
    "cloud_agent": {
      "config_assets": {
        "include_excluded": [".env.cloud"]
      }
    }
  }
}
```

The existing `runtime_env.env_files` mechanism should remain the preferred way to load env-file contents as runtime environment variables. `include_excluded` is for files that need to exist in the cloud config assets tree at their usual paths.

## Implementation Notes

`copy_config_assets` currently skips an excluded top-level directory before descending into it. To support `include_excluded`, the implementation may need a second pass over the explicit include list after the normal copy pass.

Keep the behavior predictable:

- interpret include paths relative to local `CONFIG_DIR`;
- copy to the same relative path under the target config assets directory;
- preserve the existing top-level size limit for explicitly included files/directories;
- never follow symlinks;
- report missing include entries in the manifest as missing rather than silently succeeding.
