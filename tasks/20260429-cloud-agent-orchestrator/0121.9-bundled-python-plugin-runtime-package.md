# Bundled Python Plugin Runtime Package
Create a normal bundled-Python distribution for Crystal Lattice so arbitrary
plugins and their dependencies can be installed and imported like they are in a
standard Python environment.

## Requirements checklist

  of running the application through PyInstaller's frozen importer.
- [x] Make this bundled-Python runtime the supported package shape for
  arbitrary dynamic plugin installation.
- [x] Add a `crystal-lattice bundle` command, available only from the full

## Background

The application is plugin based, so the user-facing desktop/local package must
support installing arbitrary Python plugins with arbitrary Python dependencies.
PyInstaller `--onedir` and `--onefile` packages are still frozen runtimes: they
run through PyInstaller's bootloader and import hooks, and they only reliably
support modules and data collected at build time. That conflicts with an
arbitrary plugin system where dependencies are discovered and installed later.

During `0121.8`, a real installed-bundle test exposed this class of issue with
`message-export-actions`. The plugin and dependencies installed into the plugin
cache, but a transitive dependency used dynamic import behavior that did not
match PyInstaller's frozen runtime. Adding plugin-specific hidden imports or
moving plugin imports would only hide one case and would not satisfy the
platform requirement.

The distribution path should therefore be straight:

1. Release and install the bundled-Python package for desktop/local use. It is
   the normal product package and supports arbitrary dynamic plugins.
2. From that full package, users who need a smaller/config-specific deployment
   can run `crystal-lattice bundle --config ...` to create an optimized
   PyInstaller artifact with selected plugins preinstalled.
3. Optimized PyInstaller artifacts are terminal outputs, not build tools. They
   should not support creating further bundles.

## Proposed Implementation Plan

Added during task creation for planning and final approval before
implementation.

1. Inspect existing binary build, runtime layout, and CLI command code.
   - Start with `scripts/build_crystal_lattice_binary.py`.
   - Identify the best CLI home for a new `bundle` command in
     `application/python/agent_terminal_app`.
   - Reuse useful staging pieces where they are not PyInstaller-specific:
     default config copying, selected plugin metadata, runtime layout metadata,
     archive naming, and smoke-test helpers.

2. Choose and document the bundled Python source.
   - Prefer a redistributable runtime such as `python-build-standalone` for
     macOS/Linux/Windows if it fits repository constraints.
   - Alternatively, package a venv-style runtime produced from the build host
     for the first platform-specific implementation.
   - Record platform and ABI constraints explicitly.

3. Add a new bundled-Python distribution builder.
   - Proposed script: `scripts/build_crystal_lattice_python_runtime_package.py`.
   - Output a package layout similar to:

     ```text
     crystal-lattice-python-runtime/
       bin/crystal-lattice
       python/
         bin/python
         lib/pythonX.Y/...
       app/
         application/python/agent_terminal_app/...
         core/python/agent_app/...
         core/python/agent_core/...
       bundled_plugins/
       runtime-layout.json
     ```

   - The launcher should run the packaged interpreter, for example:
     `python/bin/python -m agent_terminal_app ...`.
   - This is the only package shape that should be produced for general product
     distribution.

4. Wire plugin installation to the packaged interpreter.
   - Set runtime layout/config so `plugin_policy.python_executable` points at
     the packaged Python by default.
   - Keep user overrides via `CRYSTAL_PLUGIN_PYTHON` and
     `plugin_policy.python_executable`.
   - Preserve normal plugin cache behavior outside the immutable package
     directory.

5. Add the optimized bundle command to the full package.
   - CLI shape:

     ```bash
     crystal-lattice bundle --config path/to/config.json --output dist/
     ```

   - The command should build a config-specific PyInstaller artifact using the
     bundled Python runtime and the same selected-plugin preinstall logic as
     `scripts/build_crystal_lattice_binary.py`.
   - Factor the existing PyInstaller build script into an importable API so
     both the script and CLI command call the same implementation.
   - The bundled-Python package should include whatever build-time Python
     dependencies are required for this command, such as PyInstaller, or
     document/install them as a package extra if we decide not to include them
     by default.

6. Ensure optimized artifacts cannot build more optimized artifacts.
   - The optimized PyInstaller artifact should not include the bundler
     implementation, build-time dependencies, or `bundle` command.
   - Running `crystal-lattice bundle ...` from an optimized artifact should
     fail with a clear unsupported-command message, or the command should not
     appear there at all.

7. Preserve selected plugin preinstall semantics where useful.
   - Selected/default plugins may still be preinstalled into the bundled Python
     environment for faster startup.
   - Non-selected plugins should remain installable normally, with no
     PyInstaller hidden-import requirements.
   - Optimized PyInstaller outputs should preinstall only the plugins selected
     by the supplied config and should disable arbitrary dynamic plugin
     installation by default.

8. Add package-level E2E tests.
   - Build/extract the bundled-Python runtime package.
   - Start the app from the packaged launcher with a temp config that references
     `path:${env:BUILTIN_PLUGINS}/message-export-actions`.
   - Assert startup succeeds, application actions are registered, plugin cache
     contains `message-export-actions@...`, and dependency dist-info entries
     such as `markdown` and `xhtml2pdf` are installed in that cache.
   - Run `crystal-lattice bundle --config ...` from the bundled-Python package
     and assert it creates an optimized PyInstaller artifact.
   - Start the optimized artifact and assert selected/preinstalled plugins load.
   - Assert the optimized artifact does not support running `bundle`.
   - Add a second smoke test for a simple model/tool request only if it can run
     without network cost, for example with local Ollama.

9. Update docs and release guidance.
   - Make the bundled-Python package the only general distribution artifact.
   - Document optimized PyInstaller bundles as artifacts users create from the
     full package for a specific config.
   - Explain that optimized artifacts are smaller/runtime-only and cannot
     create further bundles.

10. Verification.
   - Run focused plugin manager tests.
   - Run the new bundled-Python installed-package E2E.
   - Run the new full-package `bundle --config` E2E.
   - Run existing PyInstaller layout/frozen rejection tests to ensure the
     boundary remains clear.
   - Run existing cloud runtime bundle tests because they share selected
     plugin metadata/preinstall logic.
