# Per-model token rates, ollama pricing sync, and `$include` config merging

Enable accurate cost tracking for OpenAI-compatible endpoints (ollama cloud
models) that report tokens but no cost: allow per-model rate overrides in the
reference provider plugin, generate a rates file from ollama's official
pricing page, and let config objects include external JSON files.

This task is a follow-up to `tasks/20260920-generic-cost-tracking.md`
(checkpoint 1 complete; cost tracking records per-request rows and stamps
session totals). It is executed separately from that task's remaining
checkpoints.

## Requirements checklist

- [ ] Per-model token rates: the reference openai-compatible provider's
  usage extension optionally accepts per-model rate overrides; when the
  active model matches a configured per-model entry, those rates are used to
  compute cost; otherwise the existing base `token_rates` behavior applies.
- [ ] Pricing sync script: a repository script fetches the official ollama
  cloud pricing page, parses the model pricing table, and generates a
  standalone JSON file with per-model rates in the format the usage extension
  consumes.
- [ ] `$include` config merging: the config parser supports a special
  `"$include": "path/to.json"` key in any config object; the referenced JSON
  file's content is merged into that object using the same merge machinery as
  config mixins, and the `$include` key is consumed so downstream config sees
  only the merged result.
- [ ] End-to-end: a rates file generated by the script can be referenced via
  `$include` from a user config, and a request through the reference provider
  with a matching model computes cost from the per-model rates.

## Open requirement questions

- **Per-model rates config shape (public config surface).** Options: keep
  `token_rates` as the base and add a sibling mapping such as
  `model_token_rates: {"<model>": {"input": .., "cached": .., "completion": ..}}`;
  or allow `token_rates` itself to be keyed by model. Recommendation: separate
  `model_token_rates` mapping — keeps the existing flat `token_rates` contract
  unchanged.
- **Model key matching rule.** Config/agents use ollama tags like
  `glm-5.2:cloud` while the pricing page lists `glm-5.2`. Decide the lookup
  normalization (recommendation: strip a trailing `:cloud`-style suffix, or
  match on the longest prefix before `:`), and whether matching is exact after
  normalization.
- **Script output location and default.** The script writes a JSON file the
  user `$include`s. Decide the default output path (recommendation: explicit
  `--output` argument, defaulting to `~/.crystal/ollama-cloud-rates.json`) and
  confirm the generated file is not committed to the repository.
- **`$include` path semantics.** Relative paths resolved against the including
  config file (recommendation) or the process working directory; whether env
  placeholders like `${env:...}` apply to the include path (they do for plugin
  specs — recommend supporting them); cycle and depth handling (recommend:
  mirror mixin guards: error on cycles, bounded depth).

## Supporting details

**Verified facts (2026-09-20):**

- Ollama's OpenAI-compatible endpoint reports only token counts — no cost.
  Non-stream and streaming (`stream_options.include_usage`) responses both
  carry `prompt_tokens`, `completion_tokens`, `total_tokens`, and
  `prompt_tokens_details.cached_tokens`; there is no `cost` field.
- Official pricing source: https://ollama.com/cloud — "Model pricing" table,
  prices per million tokens, columns: Model | Input | Cached input | Output.
  A separate "Peak pricing" table (12:00–18:00 UTC, Mon–Fri) affects only
  some deepseek models; other models keep flat rates. **No machine-readable
  pricing API exists** — the HTML table is the only official source, so the
  script must parse HTML.
- Example official rates ($/M tokens, input/cached/output): `glm-5.2`
  1.40/0.26/4.40; `glm-5.3` 1.40/0.26/4.40; `glm-5.3-flash` 0.15/0.03/0.50;
  `glm-5.1` 1.00/0.20/3.20; `gpt-oss:120b` 0.15/0.014/0.60; `kimi-k3`
  3.00/0.30/15.00. A few models list no cached-input price (e.g.
  `qwen3.5:397b`).
- The user's live config (`~/.crystal/config.json`, agent `glm-ollama`) runs
  `glm-5.2:cloud` with `token_rates {input: 1, cached: 0.2, completion: 3.2}`
  — those are the official **glm-5.1** rates, so current tracked costs
  undercount glm-5.2 by roughly 27–29%. This task's features exist to fix
  that class of drift.

**Where the rates are consumed today:**

- `plugins/reference-openai-compatible-provider/src/reference_openai_compatible_provider/usage_extension.py`:
  - `_usage_cost` (line ~121) — provider-returned cost wins; otherwise cost is
    computed from `token_rates` (`input`, `cached`, `completion`, $/M
    tokens) when present.
  - `get_config_schema` (line ~620) declares the flat `token_rates` schema.
  - The extension runs at `priority: int = 60` so it stamps
    `usage_bucket`/`usage_total_cost` before the cost tracking extension
    (priority 70) records. Keep this ordering intact.

**Where config parsing happens:**

- `core/python/agent_app/config.py`: `load_raw_config` (line 112) →
  `resolve_placeholders` (line 380, `${env:...}`-style resolution) →
  `resolve_config_mixins` (line 559). `load_resolved_config` (line 124)
  orchestrates. `application_future.py` calls the same pipeline
  (`resolve_config_mixins` at line ~405).
- Mixin merge machinery: `core/python/agent_app/config_merge.py`
  (`merge_config`, `MERGE_KEY`, deep/shallow modes) plus mixin guards in
  `config.py` (`_coerce_mixin_refs`, cycle detection, `mixin_policy.max_depth`,
  structured error entries `{type, path, detail}`). "Merge the same way as
  mixins" means: reuse `merge_config` with the mixin default mode and error
  reporting; consume the control key (`$include`) like `$mixin_refs` is
  consumed.
- The `$include` step must define its position in this pipeline (placeholder
  resolution order matters if include paths use env placeholders).

**Conventions:**

- Tests: config parser behavior → `core/python/tests`; usage extension
  behavior → `plugins/reference-openai-compatible-provider/tests`; script →
  a test with a fixture HTML snapshot (no live network in unit tests; live
  fetching can be a marked integration test).
- Docs: plugin authoring/user docs live under `plugins/docs/` (see
  `plugins/docs/index.md`); config behavior docs follow the documentation
  ownership rules in the root `AGENTS.md`.

## Execution plan

Status: Draft

### Approach

1. **Per-model rates (usage extension).** Add an optional per-model rates
   mapping to the usage extension config (shape per open question above;
   default recommendation: `model_token_rates`). In the cost-computation path,
   resolve the effective rates: per-model entry for the active model if
   present, else base `token_rates`, else no estimation. Update
   `get_config_schema`. Add unit tests covering: per-model override wins,
   fallback to base rates, no rates → no estimated cost, and suffix
   normalization if adopted.
2. **Pricing sync script.** Add `scripts/fetch_ollama_cloud_pricing.py` (or
   similar): fetch https://ollama.com/cloud, parse the "Model pricing" table
   (and decide how to treat the peak-pricing table — recommendation: skip it
   and note it in the output file's metadata), and write a JSON file mapping
   model names to `{input, cached, completion}` rates plus a `generated_at`
   timestamp. Handle models without cached pricing (omit the key). Include a
   `--output` argument. Test against a checked-in HTML fixture; optionally a
   network-marked integration test.
3. **`$include` merging.** In `core/python/agent_app/config.py`, add an
   include-resolution step that walks the config tree; when any object
   carries `"$include"`, load the referenced JSON file and merge it into that
   object via the same `merge_config` machinery mixins use (default mode from
   mixin policy; `$merge` directives in the included file honored like
   mixin-carried directives), then remove the `$include` key. Guards: cycle
   detection, depth bound, structured errors for missing/unparsable files.
   Decide pipeline position (recommendation: after `resolve_placeholders`, so
   include paths support `${env:...}`, and before `resolve_config_mixins`,
   so included content can carry mixin refs). Unit tests in
   `core/python/tests`: include at root/provider/agent levels, nested
   includes, env-placeholder path, missing file error, cycle error, `$merge`
   directive behavior, `$include` key not visible downstream.
4. **End-to-end verification.** A test (or documented manual check) that
   chains all three: script fixture output → `$include` in a config →
   reference provider request with a matching model → cost computed from the
   per-model rates (can reuse the cost-tracking integration test style with a
   stub chat-completions endpoint).

### Implementation decisions and open questions

- The four open requirement questions above must be answered (or a
  recommendation approved) before implementation starts; they shape public
  config surface and script behavior.
- Peak pricing is out of scope for rate values (flat rates only) unless the
  user asks for it; the script should record in output metadata that peak
  pricing exists for some deepseek models.
- The script targets ollama cloud pricing only; other OpenAI-compatible
  vendors keep manual `token_rates`/per-model entries.
