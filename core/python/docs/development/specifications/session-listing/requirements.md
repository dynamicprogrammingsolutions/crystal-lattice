# Application session-listing requirements

These requirements track the live state relative to the
[application session-listing specification](index.md).

| ID | Requirement | Implementation | Verification | Documentation | Evidence |
|---|---|---|---|---|---|
| SLIST-001 | `AgentApplication` provides one shared ordered session-summary collection, exact unfiltered summary lookup, structured diagnostics, filter schema access, and filter-evaluator installation through `SessionListService`. | Implemented | Automated | Documented | `agent_app/application_future.py`; `agent_app/session_listing.py`; `core/python/tests/test_application_session_listing.py`; `plugins/docs/application-plugins.md` |
| SLIST-002 | Session stores expose opaque live-session records with identity, modification time, and equality-comparable revision, and support collection and exact-record lookup without exposing storage paths. | Implemented | Automated | Not applicable | `agent_app/sessions.py`; `test_filesystem_session_store_enumerates_opaque_records` |
| SLIST-003 | A complete summary contains record identity and modification time, a normalized first-user-message preview, session metadata excluding `native_messages`, contributed fields, and stable title/subtitle/meta presentation. | Implemented | Automated | Documented | `agent_app/session_listing.py`; `test_agent_application_builds_shared_summaries_and_plugin_order`; `test_session_list_http_contract_serializes_shared_summaries`; `plugins/docs/application-plugins.md` |
| SLIST-004 | Valid `session_list` application actions execute in plugin and declaration order with only declared inputs and application lifecycle context, may contribute JSON-serializable non-reserved fields and ordering, and fail independently with diagnostics. | Implemented | Automated | Documented | `agent_app/session_listing.py`; session-list fixture tests; `plugins/docs/actions.md` |
| SLIST-005 | Session-list ordering defaults to descending modification time and composes valid contributed order declarations deterministically while ignoring invalid, incomplete, incompatible, or conflicting declarations with diagnostics. | Implemented | Automated | Documented | `agent_app/session_listing.py`; ordering tests in `core/python/tests/test_application_session_listing.py`; `plugins/docs/actions.md` |
| SLIST-006 | Presentation fields resolve dotted summary paths, apply deterministic role/order/template/datetime rules, and fall back from title fields to preview and then an ID-derived title. | Implemented | Automated | Documented | `derive_session_list_presentation`; `test/fixture/session-list/v1/contract-cases.json`; `test_python_uses_shared_path_and_presentation_contract_cases`; `plugins/docs/ui-elements.md` |
| SLIST-007 | Declarative filters preserve ordered input, combine paths and active filters according to their typed contract, report invalid declarations and values without losing unrelated filters, run before limits, and do not affect exact lookup. | Implemented | Automated | Documented | `agent_app/session_filters.py`; `core/python/tests/test_application_session_filters.py`; filter seam and exact-summary tests; `plugins/docs/ui-elements.md` |
| SLIST-008 | An unreadable or malformed stored session and an invalid plugin contribution do not fail the collection; the service returns safe fallback summary values and structured diagnostics. | Implemented | Automated | Documented | malformed-record Core and HTTP tests; action/field/order diagnostic tests; `plugins/docs/actions.md` |
| SLIST-009 | Within one application instance, complete summaries are reused only while record revision and list contract token match; saves, deletes, external changes, and missing records invalidate stale results. | Implemented | Automated | Not applicable | `SessionListService._cache`; cache, save-invalidation, external-change, and malformed-record tests |
| SLIST-010 | HTTP and terminal adapters delegate session listing and exact lookup to `AgentApplication`; HTTP preserves the `{"sessions": [...]}` envelope and maps missing exact IDs to `404`. | Implemented | Automated | Documented | `application/python/agent_terminal_app/server.py`; `terminal_app.py`; `application/python/tests/test_session_list_http_contract.py`; server delegation tests |
| SLIST-011 | `SessionListService` retains its existing public method signatures and return types while selected implementations receive opaque application context and keep cache, deadline, worker, scan, placeholder-state, and storage-backend concepts out of the public surface and shared configuration model. | Not started | Unverified | Pending | — |
| SLIST-012 | Metadata enumeration establishes current session membership from identities and attributes without opening session content before the initial implementation's foreground full-resolution interval starts. | Not started | Unverified | Pending | — |
| SLIST-013 | An unfiltered unlimited list returns one ordinary summary-shaped entry for every metadata-discovered session; unresolved entries use content-free fallback values and normal presentation without exposing implementation state. | Not started | Unverified | Pending | — |
| SLIST-014 | Complete summaries remain reusable across application runtimes, and unchanged records with compatible revisions and summary-contract fingerprints do not require session-content reads. | Not started | Unverified | Pending | — |
| SLIST-015 | The initial implementation attempts required full resolutions in descending modification time, waits no longer than its privately configured foreground interval after enumeration, and continues unfinished work for later calls without requiring client changes. | Not started | Unverified | Pending | — |
| SLIST-016 | While unresolved entries remain, complete summaries use established ordering and precede metadata-only summaries ordered by descending modification time; filters conservatively retain entries whose unavailable data prevents a conclusive decision, and limits remain last. | Not started | Unverified | Pending | — |
| SLIST-017 | Concurrent calls share compatible in-flight work; background resource use and retries are bounded; blocking reads do not hold the service lock or request event loop; and application close or reload releases implementation-owned resources. | Not started | Unverified | Pending | — |
| SLIST-018 | Persistent derived state is private, transactional, bounded, and recoverable; corruption or unavailability degrades safely without changing source sessions, and diagnostics and logs do not expose session content or credentials. | Not started | Unverified | Pending | — |
| SLIST-019 | Application-owned saves and deletes and externally observed revisions converge persistent and in-memory summaries without allowing obsolete work to overwrite a newer record or contract. | Not started | Unverified | Pending | — |
| SLIST-020 | The server delivers the target through existing application and HTTP contracts without changes to mobile, desktop, frontend SDK, or other client packages. | Not started | Unverified | Pending | — |
